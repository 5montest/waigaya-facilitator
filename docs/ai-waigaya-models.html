ワイガヤのAI進行・記録係：モデル選定と費用

更新日：2026年10月8日／版：0.3／状態：OpenAIのみのMVPを実装、既存キーで接続確認済み

MVPはOpenAIだけで構成する。音声認識・議論の検討・音声合成を分け、端末の発話検知と停止はモデルの応答を待たずに動かす。コストを抑える候補は比較するが、品質確認前に通常モデルを安価なモデルへ切り替えない。

前版で調べた他社モデルも比較資料として残す。MVPではSonioxなどの新たなプラットフォームへの登録は必要ない。公開料金の比較と、実APIで確認した結果を以下に分けて記載する。他社の料金表は2026年10月7日の確認値であり、MVP後の採用時に再確認する。

1. MVPはOpenAIのモデルを役割ごとに使う

部品 初期設定 比較・変更候補 選定理由と限界
音声認識 gpt-transcribe gpt-live-transcribe、gpt-realtime-whisper 発話を区切ってから認識し、費用を抑える。途中の文字表示が必要ならライブ版へ変更
整理・質問 gpt-6.1-sol gpt-6-luna Solを評価の基準に置き、Lunaへ置き換えた際の条件保持・質問の質を確認する
音声合成 gpt-4o-mini-tts、声は marin 継続運用時は gpt-realtime-2.1-mini へ移行評価 人が承認した文章をストリームで読み上げる。現行スナップショットの提供終了に対応する必要がある
発話検知・割り込み停止 ブラウザ内の音量判定 実機評価後に検知方法を改善 LLMや文字起こしが遅れても端末側で再生を止める

gpt-realtime-whisper は正式な音声認識モデルで、発言内容の検討や音声生成は行わない。3種類の音声認識は同じ画面で切り替えられる。MVPでは自動の話者区別は行わず、話者を不明として記録する。Whisper、Realtime文字起こし

この構成は品質検証の開始点である。上位モデルも誤るため、生成した発言は人が確認し、決定事項は人が記録する。実装・操作手順は README に記載した。

2. 音声認識は区切り後の認識と逐次表示を比べる

1本の音声を60分送る場合の公開料金を示す。税、無料枠、契約割引は含まない。

OpenAIのモデル 音声1分 音声60分 MVPでの動き
gpt-transcribe $0.0045 $0.27 発話終了又は12秒の区切りを送ってから認識
gpt-live-transcribe $0.017 $1.02 話している途中の暫定結果を表示
gpt-realtime-whisper $0.017 $1.02 話している途中の暫定結果を表示

Transcribeの料金・仕様、Whisperの料金・仕様、OpenAI料金。Realtimeという接続方法だけで料金や結果の出方が同じになるわけではない。

同じ24kHz PCM音声をWebSocketで送り、端末が発話の区切りを通知する。暫定結果は同じ発言を更新し、確定結果が前後して届いても音声の区切り順で記録する。時刻は送ったPCMの範囲であり、モデルが返した単語の時刻ではない。

3. LLMは入力20万・出力2万トークンの同じ条件で比べる

60分の会議で、40回の検討、1回平均5,000入力・500出力トークンを仮定する。出力には課金対象の思考トークンも含める。これは利用量の仮説であり、各社で同じ文章のトークン数が一致するわけではない。実測では各社の課金使用量で再計算する。

単価は100万トークンあたりの米ドルで、キャッシュなし、通常のオンライン処理、短いコンテキストの料金を使う。入力20万は40回の合計であり、1回に20万を渡す想定ではない。

Gemini 3.8 Flashは2026年末までの料金を使った。公式に示された2027年1月からの単価は入力$1.50、出力$7.50で、同じ利用量なら$0.450になる。DeepSeekの幅はキャッシュなしの閑散・繁忙時間帯によるもので、会議時刻に合わせて見積もる。過去世代のGemini 3.1 Flash-Liteも入力$0.25・出力$1.50と安いが、初期評価は現行候補を中心にし、必要なら追加する。

4. 音声合成は生成した使用量で計算する

MVPでは gpt-4o-mini-tts に承認文を送り、PCM音声を受信しながら再生する。日本語に対応するが、声は英語向けに最適化されているため、日本語の発音・自然さを実際に聞いて評価する。音声合成の仕様

公開料金は文字入力100万トークンあたり$0.60、音声出力100万トークンあたり$12である。MVPのバイナリ音声応答から実使用トークンを取得する集計は未実装のため、画面と試算ではTTS費用を不明として残す。未知の分単価を置いて総額を確定しない。OpenAI料金

現行の既定スナップショット gpt-4o-mini-tts-2025-12-15 は2027年1月6日に提供終了予定である。短期のMVP検証に使い、継続運用では公式の移行先 gpt-realtime-2.1-mini で承認文の読み上げ・割り込み停止・費用を評価する。提供終了の案内

5. MVPの音声認識とLLMは、会議1時間で$0.30〜1.62の試算

前述のLLM入力20万・出力2万トークン、音声認識60分を仮定する。以下にはTTS費用を含めていない。総費用は各金額に音声合成等を加えた値になる。

音声認識 LLM STT＋LLM／会議1時間 扱い
GPT Transcribe GPT-6.1 Sol $0.87＋TTS等 MVPの初期設定
GPT Transcribe GPT-6 Luna $0.30＋TTS等 品質が同等と確認できた場合の節約候補
GPT Live Transcribe / Realtime Whisper GPT-6.1 Sol $1.62＋TTS等 途中の文字表示を使う場合
GPT Live Transcribe / Realtime Whisper GPT-6 Luna $1.05＋TTS等 逐次表示と軽量LLMの組み合わせ

計算式は「音声認識＋LLM入力単価×0.20＋LLM出力単価×0.02」。会議後の議事録作成、再試行、通信・保存、サーバー運用、税、為替は含まない。使用量の仮説であり、上限ではない。

LLMを常時呼ぶより、端末が会話状態を保持し必要なときだけ検討を依頼するほうが呼び出しを抑えられる。MVPは人による依頼で検討する。文字起こしはマイク起動中の音声を送るため、長時間の無音をバッファから消しても、送った時間を無料とは扱わない。

LLM入力を5倍に増やせば入力料金も5倍になる。現在は黙って文脈を切り捨てず、入力の文字数上限を超えたら会議を分けるよう案内する。正確な記録を保った文脈抽出は今後の実装対象である。

6. 日本語ワイガヤの品質を別々に測る

評価用の会話と正解は、モデルの出力を見る前に人が用意する。上位モデルの回答をそのまま正解にはしない。初期の回帰確認には想定会話を使い、最終判断には実際の会議録音と、別の会議による検証も必要になる。

評価対象 見る内容 初期の採用条件案
音声認識 日本語の文字誤り、専門語、否定、数値、話者取り違え 重要語の誤りを人が確認し、比較対象より悪化した条件を把握する
介入判断 待つべき場面、呼びかけ、解消済みの質問、堂々巡り 明示的依頼の見逃しと不要な介入を別々に集計する
整理 意見の違い、条件、未決事項、発言の根拠 根拠のない決定・担当者・期限の確定は評価セットで0件
質問 一度に一つか、誘導していないか、議論に役立つか 提供元を隠して参加者が5段階評価。平均4以上を初期目標にする
音声合成 読み間違い、聞き取り、声の自然さ、生成待ち 同じ文章で聞き比べ、重大な内容の読み違いを残さない
制御 古い候補の取消、人の発話時の停止 モデルが変わっても取消・停止の確認条件を満たす

数値条件は本提案であり、実証済みの品質基準ではない。評価セットで誤り0件でも、未知の会話で誤りが出ない保証にはならない。初期の比較では、複数人、重なった声、沈黙、反対意見、皮肉、言い直し、専門語、長い文脈を含める。

LLMだけを比較するときは、人が確認した同じ文字起こしを使う。次に各音声認識の出力を使って全体を比較する。これにより、LLMの違いと、入力の誤りによる影響を区別できる。

7. 軽量モデルへの切り替えは品質確認後に行う

MVPはGPT-6.1 Solを初期設定とし、GPT-6 Lunaと同じ文字起こしで比較する。上位という位置づけだけを品質の証明にしない。条件保持、未確認事項の扱い、質問の有用性を人が確認したうえで、品質基準を満たす最安の候補を通常処理に使う。

40回中36回をLuna、4回をSolへ振り分ける場合、同じ平均トークン数ならLLM費用は$0.087、GPT Transcribeを加えて$0.357＋TTS等／時間となる。二段処理でSolがLunaの回答も検査する場合は、両方の費用と追加の遅延がかかる。

切り替えには複数案の条件衝突や根拠の修正などの会話状態を使う。安価なモデルが論点を見落とすと切り替え判断自体も失敗するため、構成全体で評価する。自動切り替えはまだ実装・有効化していない。他社を加えた比較はMVP後に行える。

8. 接続確認は完了、実会議の品質を次に評価する

指定された既存キーをファイルから読み込み、2種類のLLM、3種類の音声認識、音声合成を実APIで確認した。キーを複製したり、ブラウザへ渡したりしない。

4.05秒の生成音声「まず、利用者の聞き取り結果を確認しましょう。」は、3種類の音声認識で同じ文字列に確定した。これは短く明瞭な音声での接続確認である。複数人の重なりや雑音下での精度を示すものではない。接続結果、生成音声

同じ想定6会話で初回比較を実施し、指示を調整して再比較した。以下は調整後の1モデルにつき各会話1回の結果で、繰り返し測定した性能値ではない。

モデル 構文・根拠参照が正常 初期の行動条件に一致 応答時間中央値 6件のLLM概算 人の品質採点
GPT-6 Luna 6/6 6/6 4.0065秒 $0.001253 未実施
GPT-6.1 Sol 6/6 6/6 7.892秒 $0.022884 未実施

初回は両方とも、問いが解消済みの場面で担当者を尋ね、行動条件の一致は各5/6だった。依頼範囲外の確認を追加しないよう指示を調整すると、この場面の出力は整理へ変わった。初回、調整後

調整後も、Lunaは「価格と納期を確認する」という発言を「価格を先に確認する」と整理した。この順序の解釈は採点時に確認する必要がある。Solは順序を追加せずに整理した。また、「少し考えさせてください」という場面でSolは待機、Lunaは質問を返した。機械的な行動条件の通過だけで、内容の正しさや待つ判断まで合格とはしない。

次は提供元を隠した採点と、複数人の録音・会議用マイクでの認識精度、エコー、割り込み停止の測定を行う。初回の費用・速度の差だけでLunaへの変更を決めない。試作版は文字起こしの追加・修正、候補の手動承認、割り込み停止、決定事項の確認、SQLite保存に対応している。

料金は公開値に基づく概算。実請求額と、日本語の実会議での品質は別途確認する。
