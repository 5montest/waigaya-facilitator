# 入力監視の復旧と、分断された議事録の統合

## 変更内容

入力の心拍が2.5秒遅れた際、従来はDiscordの会議全体を直ちに終了していました。
これを「AI音声を停止して、同じ会議で30秒間の復旧を待つ」動作へ変更しました。
待機時間は遅延を検出した時点から数えます。イベントループ自体が一時停止した場合も、再開直後に即終了しません。

- 入力確認ができない間は、生成中・再生待ち・再生中のAI音声を取り消します。
- 同じ入力接続の心拍が戻れば、同じ会議IDで続けます。中断した音声は再開しません。
- pause、終了、STT接続の障害、保存障害、復旧猶予の期限切れを、心拍だけで解除しません。
- 復旧しない場合、Discord Botは既存の障害終了処理へ進み、保存済み原本から議事録を作ります。
- 実際のWebSocket切断・VC切断は従来どおり障害終了します。通信切断全般を自動再接続する変更ではありません。
- 入力確認が途切れた区間は記録欠損の可能性として保持します。確実に発言が失われたという意味ではありません。

`microphone_timeout` イベントに心拍経過時間・監視タイマーの遅延・復旧猶予を、`microphone_recovered` に復旧所要時間を保存します。会議本文や秘密値は診断イベントへ追加しません。
これにより、次回は処理の遅延と入力接続の状態を調べやすくなります。過去のログにない遅延原因を、この変更だけで断定することはできません。

## 分断された議事録の復旧

運用者用の `scripts/merge-minutes.js` は、終了済みの複数会議を別の統合会議として保存します。通常の会議操作では使いません。

1. 保存済みの原発言から、根拠ID・revision付きの議事録JSONを作り、確認します。
2. 非公開JSONに `{sources:[{id,revision},...],title,document}` を保存します。公開リポジトリには入れません。
3. 進行中・一時停止中の会議がないことを確認し、サービスを停止します。SQLiteをバックアップします。
4. `node scripts/merge-minutes.js --database <DB> --manifest <非公開JSON> --offline-confirmed` を実行します。
5. サービスを起動します。既存の送信予約・結果照合処理を使って、固定フォーラムへ未確認の統合版を投稿します。
6. 投稿先・添付内容・原本保存を確認し、元の投稿に統合版へのリンクを案内します。

同じ通知済み固定VC・フォーラムの会議に限定します。原会議は書き換えません。原発言IDが衝突した場合や、原本の版が変わった場合、送信結果不明の投稿がある場合は拒否します。同じ原会議の組合せを再実行しても新規の統合会議は増やしません。

統合版は人による承認を付けず、API利用量も重複計上しません。追加のモデルAPI呼び出しはありません。発言原本・根拠・中断区間は保持し、文字起こし全文は自動公開しません。未記録の発言を復元する機能ではありません。

## 検証と導入

- `node --test --test-concurrency=1 test/runtime-faults.test.js test/minutes-merge.test.js`
- 全体：`node --test --test-concurrency=2 test/*.test.js`（共有ホストではブラウザ用ロック下で実行）
- 模擬Discord＋HTTP/WebSocket＋SQLiteで、復旧、期限切れ、pause、旧TTS片の破棄、イベントループ停止、統合の原本保全・重複防止を確認します。
- 実通話の音声品質と実ネットワーク障害は別途確認が必要です。自動テストを実通話の確認と呼びません。

DBの破壊的変更はありません。コードを旧コミットへ戻しても追加した状態フィールドは保持できます。公開後のロールバックでは、現在のDBと公開IDを維持してください。投稿前のバックアップをそのまま戻すとDiscordの投稿との対応を失うため、復元が必要な場合はまず投稿IDを控えて照合します。統合前の原会議は削除していません。

統合版は統合時点の原本の写しです。その後の訂正は統合版を対象に行ってください。旧会議の訂正を統合版へ自動同期する機能はありません。
