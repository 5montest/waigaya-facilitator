# PR #1：固定VC・開始一回の運用への変更

2026年10月9日更新。着手時HEAD `86fe067`、ブランチ `feat/meeting-lifecycle-minutes`。固定運用、声の呼びかけ、自動退出・公開、復旧、テスト、資料を同じPRで変更した。本番デプロイ・mainへのマージ・新版の実Discord投稿は行っていない。

## 一括対応結果

| 要件 | 結果と判断 |
|---|---|
| 固定VC・固定フォーラム | 実装済み。ID・種別・ギルド・Bot権限を検証し、設定をSQLiteへ登録。別VC開始・移動録音・別公開先への変更を拒否 |
| 開始一回 | 実装済み。引数なしstartでon_call。モード・保存先メニューを出さず、題名はJST日時＋VC名。通知成功前に記録しない。開始を排他化 |
| 声の質問 | 実装済み。人間の確定STTから冒頭呼称を検出し、voice_request→専用プロンプト→LLM→TTS。名前の話題・部分STT・再送・Bot音源・既知エコーを除外 |
| ターン・取消 | 維持・拡張。最新一件の置換キュー、revision・TTL・入力・VAD検査。意味ある確定発言、訂正、モード変更で古い回答を取り消し、後着TTSを破棄 |
| 終了・自動退出 | 実装済み。0人から3分、pause復帰状態を保持。STT最大13秒ドレイン→終了ジョブ保存→VC退出→生成・投稿。無音だけでは終了しない |
| AI下書き自動公開 | **仕様変更**。通知済みの固定範囲に限り、正式版をAI生成・未確認として自動投稿。人の承認属性は空。途中要約は不可 |
| 人の後日確認・訂正 | 実装済み。人の確認は実際の確認者・日時を別版に保存。旧AI版を書き換えず、同じ親投稿へ新版を追記 |
| 永続ジョブ・冪等性 | 実装済み。既存の予約・ハッシュ・識別子・照合を再利用。再起動後の終了途中・未公開を処理。結果不明は再送しない |
| 原本・権限・公開範囲 | 維持。原音声ファイルは作らず、文字起こし原本はSQLite。原文全文・JSONは自動公開しない。会議認可・元VC閲覧・ローカルHTTP/WS認証を維持 |
| 障害時の動作 | 応答LLM/TTS失敗は記録継続。正式生成は2回、既知未送信は3回まで。空会議は投稿省略、全欠損疑いは異常。機密本文なしのDM通知 |
| 既存負荷対策・ブラウザ | 維持。変更行保存・差分配信・高頻度抑制と既存ブラウザの手動機能。Discord機密会議のブラウザ公開は追加しない |

人の内容確認と、フォーラムへの配布を別の属性にした。全員合意、担当者、期限をAIが勝手に確定する処理は追加していない。固定運用以前の履歴を無断で新自動公開ポリシーへ移行しない。

## 主なコード変更

- `src/discord/fixed-policy.js` / `config.js` / 環境ファイル例：固定先・応答方針・猶予・自動公開・呼称設定、IDと実チャンネル検査。
- `src/discord/addressing.js` / `bot.js` / `bridge.js`：STT確定イベントの配線、依頼者と発言revision、排他・再送抑止、声からの回答と一回開始・退出。
- `src/models.js` / `controller.js`：直接質問用の情報回答プロンプト、既存構造化出力、音声依頼の文脈・TTL・再生世代、AI発言の根拠除外。
- `src/discord/completion.js` / `server.js` / `meeting.js`：DBに保存したジョブの走査、再起動時の無人猶予・終了再開。ワーカー自身はVC接続や録音を行わない。
- `src/publication.js` / `minutes.js` / `discord/minutes-publication.js`：固定・通知済みポリシーの公開検査、未確認ラベルとタグ、予約した本文の固定、人の確認別版、同じ投稿の更新。
- `src/state-sync.js`：voiceRequestsを既存の変更行保存・差分配信へ追加。DBのテーブル削除や履歴削除はない。
- `src/discord/commands.js` / `scripts/discord-setup.js`：固定運用のコマンド登録、汎用選択を非表示、非常用endと旧stopの区別。
- `test/fixed*.test.js` / `test/helpers/fixed.js`：模擬Discordの音声受信、実Opusデコード・発話検知、ローカルHTTP・WebSocket・SQLiteを通した結合・復旧テスト。

生成中に新しい確定発言が増えた際は、意味の再評価を追加せず旧候補を破棄する保守的な方式を採った。会話を邪魔しないが、別発言が続くと質問に答えない場合がある。必要なら再度呼びかける。曖昧な呼称は追加LLMを呼ばず見送るので、誤応答と費用を抑える。

## 検証・移行

着手時の既存121件を維持し、固定運用の新しいケースを追加した。[検証記録](validation.md)に実際の件数・コマンド・CIを記載する。新版の実OpenAI API・実Discord通話／投稿は実行していない。Secrets不要の既存CIで新ケースも走る。[手動受け入れ](manual-acceptance.md)を実通話のリリースゲートにする。

旧サーバーが公開ファイルを読んでいるため、別のgit worktreeで編集・クリーン導入・テストした。旧サーバーは停止も更新もしていない。以前の退出依頼で旧Botは通常停止済みであり、新Botを勝手に起動していない。

固定設定・終了ジョブ・確認属性は既存JSONへの追加。voiceRequestsは既存session_partsの追加配列。破壊的DB変更はない。ただし旧コードが新しいDBを読める保証はないので、停止バックアップと旧コード＋更新前DBでのロールバックを必須にする。[導入・ロールバック](../discord-setup.md)を参照。

## 残る制約と未確認事項

| 範囲 | 制約と対応 |
|---|---|
| 実チャンネルID・導入 | 固定VCとフォーラムの実IDは未設定。管理者が確認して導入時に一度設定。既存Guild/Application IDを維持 |
| 実音声・実権限 | 日本語呼称、重なり、エコー、DM、必須タグ、アーカイブ・ロック、実添付容量は未確認。2〜3人の受け入れを実施 |
| 呼称・前提理解 | 冒頭構文と設定した表記揺れに対応。任意語順・複雑な引用・自由な言い直しは保証しない。文脈変更は取消方式 |
| エコー | Bot音源と同一AI文字列を除外。人のマイクに混入した部分的エコーの完全除去は未実装。実通話で調整 |
| 通知・再試行 | 管理通知は開始者DM。DM拒否では届かない。状態・minutesでも確認。生成・既知未送信の上限後は手動復旧 |
| 結果不明照合 | 既存の探索上限・10分待機・管理者確認を維持。旧識別子なし投稿はURLと添付ハッシュで照合。無条件再送禁止 |
| 設定変更と旧履歴 | 旧固定先の未処理ジョブを新公開先へ移送しない。旧会議の自動公開ポリシーは変更せず履歴として保持 |
| 長時間品質・費用 | 保存・配信の600発言模擬検証を再実行し、原本・revisionを復元。新版の実1時間要約品質・会議費用・停止時間は未確認 |
| 運用機能 | 同時一会議。保持期限・削除管理・OS監視・Discord機密記録の個人認証付きブラウザ閲覧は今回の対象外 |
