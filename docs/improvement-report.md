## 安全な既定と互換性の判断

- 新規会議はminutes。モードを省略したDiscord操作は選択画面で確認するまで記録しない。
- askは文字が既定。minutes以外でも音声には `voice:true` を要求する。
- 終了後の本文は自動投稿しない。案内は開始者へのDM、取得は本人だけの応答とする。
- 操作・閲覧・共有は開始者、サーバー管理者、明示設定した管理ロールに限る。
- DiscordのHTTP / WebSocket / 履歴 / ファイルはループバックと共有認証で保護する。ブラウザでの閲覧を追加する前に遮断した。
- 再起動は停止状態へ復旧し、明示resumeを要求する。以前の環境変数による自動再開は廃止する。
- 旧会議の開始者を推測しない。移行CLIで実IDを人が指定し、時刻は不明なら不明のままにする。
- 公開結果が不明なら予約を保持して再送しない。後から二重投稿するより、運用者の照合を優先する。
- 確認済みMarkdownを版に保存し、後から訂正しても公開した版の本文を変えない。
- `stop` はAIだけ停止、`leave` は終了のまま。確認UIと既定の変更は操作ガイドで明示する。

## 検証結果

自動テストの結果と実APIの範囲は [検証記録](validation.md) にまとめた。既存57件の観点を維持し、既定モード・表示変更に合わせて音声テストに明示的なモード指定を加えた。実Discordの新機能は未確認であり、[手動受け入れチェック](manual-acceptance.md) で別途確認する。

## 残課題と次の作業

| 範囲 | 未対応・理由 | 次の作業 |
|---|---|---|
| 実Discordの受け入れ | 人の端末・通話・権限・DM・添付の確認は模擬テストで代替できない | 2〜3人でチェックリストを実施 |
| P0の運用境界 | 公開予約の結果不明を解除するUI、開始後に公開先を設定するUIがない | メッセージ照合を伴う明示的な再投稿・公開先変更 |
| 編集UI | 議事録項目の直接編集は先頭25件。原発言はページ選択と部分編集に対応。項目の根拠変更は原発言訂正・再生成で行う | 全項目のページ選択、根拠の確認と編集 |
| 決定候補の承認 | 議事録全体の確認とは分離。Discordには個別の決定を合意として記録する専用UIがない | 原発言の引用を確認した上での個別決定操作 |
| P1-1 | 長期要約と原文保持は実装。専用の論点検索・全文検索・長時間の実会議評価は未実施 | 検索と根拠ジャンプ、1時間以上の負荷・費用測定 |
| P1-2 | 会議操作ロールと閲覧制御は実装。権限の細分化、保持期限・削除管理、全参加者の明示同意管理は未実装 | 開始／共有／削除を分け、保持方針を設定後に適用 |
| P1-3 | 原本保全・再生成・停止復旧・STT再接続は実装。OS自動起動と公開結果不明の照合UIは未実装 | 運用監視・復旧手順と照合機能 |
| P1-4 | ブラウザの3モード・停止・終了・議事録取得は実装。ブラウザの個人認証、Discord会議の閲覧、一覧・検索は未実装 | 認証と会議単位の認可を先に実装 |
| P2 | 静かな自動提案・兆候別の意味評価・録音リプレイによる介入評価は仮説の段階 | 3モード比較の測定後に、評価で有効だった条件だけを追加 |
| 大規模運用 | 単一サーバー・単一会議の範囲を維持 | 多会議対応は認可と状態分離を設計してから追加 |

自動テストと架空会話の実API確認は、実会議の議事録の正しさや自律介入の有用性を保証しない。元音声の保存、外部サービスへの転送、自動削除を追加していない。
