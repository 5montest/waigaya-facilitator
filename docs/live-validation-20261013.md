# 実API・Bot動作の確認と修正（2026年10月13日）

利用者から実テストの依頼を受け、既存キーとBotアカウントを使った。対象は固定VC「会議室A」、固定フォーラム「議事録（テスト）」。**人は参加しておらず、人のマイク受信・聴取の確認ではない。** 元のSQLiteを停止状態でバックアップし、旧データを更新せず別のテストDBと端末内HTTPサーバーを起動した。

## 確認できたこと

| 対象 | 実施結果 | 確認の限界 |
|---|---|---|
| Bot接続・固定先 | 実ログイン、VC／フォーラムの種類・所属・権限を検査。startを選択なしの定義で実登録 | ユーザー本人による実start操作は未実施 |
| 合成音声の呼びかけ | 実Opusで圧縮・復号し、Discord用STTラッパーから実gpt-transcribeへ送り、確定文字から検出 | Discordの人間ユーザーの音声受信は模擬経路 |
| 直接回答・TTS | 検出した質問からgpt-6.1-solで構造化回答・根拠を生成し、実TTSを受信 | 通話参加者が回答を聴いたことは未確認 |
| VC音声送信 | 無人VCへ明示テスト接続。selfDeafで受信を止め、5.55秒の合成音声を281パケット送信。再生後に退出 | 音声の送信と再生状態まで。人の端末での聴取、割り込みは未確認 |
| 正式議事録の生成・初回投稿 | 合成音声のテストジョブをSQLiteへ投入。Botの終了ワーカーが実LLMで生成し、フォーラムへ未確認Markdownを添付 | 実start→人の会話→退出3分という経路の代用ではない |
| 訂正版 | 版2を同じ親投稿の返信に添付。人の承認属性は空のまま | 人による編集UI・実ロールの受け入れは別途必要 |

## 見つかった問題と修正

1. **接続認証が未設定で起動できない。** 既存の認証準備スクリプトでファイルを生成し、両環境ファイルから参照。秘密値はログやGitへ出していない。再利用プロファイルを指定できるテスト起動コマンドも追加した。
2. **呼びかけを聞き逃す。** 実STTが「Yガヤ」「ワイダヤ」「ワイダや」と返した。観測した表記だけを追加し、呼称のかな混在・英字大小を同一視。STTに記録係の名前のヒントを渡す。発言の原文は書き換えない。「YガヤっていうBot」のような話題は引き続き起動しない。
3. **回答を待っている間に補足が入り、黙る。** 直接依頼に限り、新しい確定発言で旧生成が失効した時は最新文脈で一回再検討する。解決済みならhold、未解決なら回答。訂正・モード変更・入力障害・次の依頼では再生成せず、再生中断の続きを再開する処理もない。
4. **返答待ちと説明が長い。** 直接回答だけreasoning.effort=low、原則1〜2文・100文字程度とした。議事録生成の推論設定やモデルは変えない。
5. **statusが実装の説明に寄っている。** 待機理由、記録の停止／再開、議事録・投稿リンク、保存失敗に絞った。回答失敗時も「記録は続いている」「もう一度呼びかける」を短く案内する。
6. **会議時刻がUTC表示で分かりにくい。** フォーラム本文を日本時間と明示して表示し、日付境界でも投稿タイトルと一致させた。既存の公開版は書き換えない。

短い比較質問の単回測定は、変更前13,844ms（入力802・出力283トークン）、変更後5,404ms（827・131）。別の実Opus経路では9,410ms（840・133）、TTSの最初のチャンクまで952ms、生成音声16.6秒だった。入力やタイミングが異なる小規模確認であり、常に5秒で返る保証や、モデル品質の同等性を示す比較試験ではない。

正式議事録は入力703・出力499トークン、11,497ms、使用量からの推定$0.006396。直接回答の2回は推定$0.004434 / $0.002964、実Opus経路は$0.003010。いずれも当該LLM呼び出しだけで、失敗試行・STT・TTSを含む総請求額ではない。STTの名前ヒントと低推論設定は[Realtime文字起こしの公式資料](https://developers.openai.com/api/docs/guides/realtime-transcription)、[GPT-6.1 Solの公式仕様](https://developers.openai.com/api/docs/models/gpt-6.1-sol)を確認した。

## 再実行と記録

```bash
# 実API・投稿のない通常テスト
npm test
# 実接続だけ
npm run verify:discord
# 少量の合成音声と実API
npm run verify:discord -- --speech
# 無人VCの音声送信だけ。人が入ったら中止し、必ず退出
npm run verify:discord -- --play-voice
```

`--speech --publish` は追加の実API費用とテスト投稿を伴う。起動中の会議サーバーと同じDBを明示し、[管理者手順](../discord-setup.md)に従う。既定では送信テスト・人の録音・議事録公開をしない。今回の初回投稿と版更新は同じ終了ワーカー／予約・送信結果保存経路で確認した。結果不明時の自動再送禁止は維持している。

テスト用Botは `npm run discord:test` で既存資格情報のプロファイルを読み、端末内の8875番ポート・独立した `data/live-validation.sqlite` を使って起動した。元の会議DBやmainへ反映していない。稼働中に人のstartがあればテストDBへ通常の会議記録が保存されるため、このDBも移行・バックアップ対象として保持する。

今回の自動テストは159件成功・失敗0（追加5件）。実APIテストは通常テストやCIへ組み込まない。実APIの合成結果はローカルresultsのJSONに保存し、音声はメモリだけで扱った。秘密値や人の会議本文はGitへ含めない。

残る確認は、人が固定VCでstart→声で要約依頼→実音声聴取→割り込み→全員退出→3分後の自動投稿まで進めること。実ロール、必須タグ、ロック・アーカイブ、長時間の品質・費用も[手動受け入れ](manual-acceptance.md)に残す。
