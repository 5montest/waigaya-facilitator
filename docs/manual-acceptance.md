# 実Discordの受け入れチェック

本番反映前のリリースゲート。以下は未実施。改善コードの自動テストとは別に、実際のBot・権限・マイクで実施する。未実施の項目を確認済みにしない。元音声を保存する設定は加えない。

## 更新前

- [ ] 稼働中の会議を参加者と確認して終了または一時停止する。
- [ ] Botと会議サーバーを停止し、SQLiteのDB・WALを含め整合性のある更新前バックアップを作る。停止後のcheckpointまたはSQLite backup APIを使う。
- [ ] ロールバックで旧コードと更新前DBを組にして復元できることを確認する。更新後原本を別保存し、旧コードで新形式DBを開かない。
- [ ] 改善ブランチを導入し、認証ファイルと両方の環境設定を用意する。
- [ ] 旧会議を参照する必要があれば、実際のサーバー・VC・開始者IDで移行する。
- [ ] 会議サーバー→コマンド更新→Botの順に起動する。Bot起動だけでは録音・公開しない。
- [ ] テスト用フォーラム `#議事録` を作り、閲覧可能なロールを明示する。Botには閲覧・親への送信・添付・スレッド送信・履歴閲覧を許可する。
- [ ] 管理者が `/waigaya setup channel:#議事録` を実行する。一般ユーザーは変更できない。設定が再起動後も残る。

## 議事録だけで完遂する

- [ ] 2〜3人で通常VCへ入る。Bot起動・入室だけでは記録されない。
- [ ] `/start` のモード選択を開く。未選択のままでは記録されない。
- [ ] 「議事録のみ」を選び、VCのチャットで送信・保存先とモードの通知を見る。選択メニューが消え、再選択・別人の選択で二重開始しない。
- [ ] 1〜2分話し、`/status` で記録中・AI音声OFFを確認する。
- [ ] `/ask voice:true` を使っても文字回答だけで、音声が出ない。
- [ ] `/pause` 後に話し、停止中の発言が文字起こしへ入っていない。
- [ ] `/resume` で同じIDを保ち、再開後の発言だけ記録される。
- [ ] `/finish` の確認をキャンセル・失効させる。記録は終了しない。
- [ ] 再度 `/finish` を確認し、原本を確定してBotが退出する。
- [ ] `/minutes` から議事録Markdown・構造化JSON・文字起こし原本を取得する。
- [ ] 下書きの根拠を原本で確認する。未確認の決定・担当・期限が確定されていない。
- [ ] 原発言を訂正すると旧議事録が要再確認になる。再生成で新しい版になる。
- [ ] 議事録項目を編集し、編集前の版と確認済み版が残る。
- [ ] 公開先を指定していない会議の全文がチャンネルへ投稿されない。

## 退出と再起動

- [ ] 人間が0人になり、Botだけ残る。新しい音声は記録せず猶予を表示する。
- [ ] 3分以内に戻る。同じ会議IDで続く。一時停止していた会議は停止のまま。
- [ ] 再び全員退出し、3分経過する。終了・議事録生成・退出が一度だけ起きる。
- [ ] 自動終了直前に手動終了しても生成が重ならない。
- [ ] 終了後にもう一度 `/start` すると新しいIDになる。
- [ ] 会議中にBotを停止・再起動する。勝手に記録せず、明示再開を要求する。
- [ ] 会議サーバーも再起動し、原本・版が残る。終了済み会議は終了状態のまま。
- [ ] 再起動後の一時停止会議を、録音再開せず `/finish` の確認で終了できる。
- [ ] `/summary` の生成中に `/finish` を使う。最後の発言を含む正式議事録が作られ、終了処理が止まらない。

## AIワイガヤと割り込み

- [ ] モードをAIワイガヤへ変更する。記録は同じIDで続く。
- [ ] 意味のある会話が増え、区切りで必要な時だけ発言する。holdも正常と扱う。
- [ ] 生成中に人が具体例を出す・問いを解消する。古い「具体的には？」が後から再生されない。
- [ ] AI発言中に「ちょっと待って」と話す。再生を停止し、残りを自動再開しない。
- [ ] 生成・待機中に議事録モードへ変更すると、TTSや後着音声が再生されない。
- [ ] quietではAIだけ停止し、記録は続く。pauseでは新しい音声送信も止まる。
- [ ] 相づち・環境音・エコーで過剰に停止しないか測る。実機で調整する。

## 確認からフォーラム投稿・訂正版追記まで

- [ ] `/start output_channel:` の明示指定がサーバー既定より優先される。
- [ ] 保存先なしでも終了・下書き取得でき、本文が勝手に公開されない。minutesの「保存先を選ぶ」で終了後にも指定できる。
- [ ] `/minutes` で原文・根拠・短い下書きを非公開確認する。25件を超える議事録項目もページで訂正できる。
- [ ] 「確認して投稿」で実際のフォーラム名・親を見られる人に公開されること・版・概要を確認する。戻る・期限切れでは承認・送信しない。
- [ ] 最終確認後、追加のpublish入力なしでフォーラム投稿が1つでき、URLが返る。実日付・議題・記録で把握した出席者を使う。
- [ ] 短い本文、確認済みMarkdown、版と識別子を確認する。JSONと全文文字起こしは自動添付されていない。
- [ ] 承認者の確認は全参加者の合意を保証しないと表示され、決定候補・確認済み決定・担当期限不明が区別される。
- [ ] 訂正・再生成した版2を再確認すると、同じ投稿への返信と新しいMarkdownになる。版1添付・承認履歴は残る。
- [ ] タグなし・既存タグ・必須タグのフォーラムで確認する。タグを勝手に作成しない。適用可能なタグがない場合は管理者向けエラーになる。
- [ ] アーカイブ・ロック・削除した投稿で更新する。権限下で復帰できる場合以外は明確なエラーとなり、別投稿を無断作成しない。
- [ ] 通常テキストにも投稿し、親メッセージと可能ならスレッドへの版更新を確認する。作成不可時は元チャンネルへの追記と表示する。
- [ ] 2,000文字超の議事録と分割添付を確認する。上限超過は未送信エラーになり、原本と確認済み版は残る。
- [ ] 本文中の `@everyone`・ロールメンション・URLで通知・意図しない埋め込みが起きない。
- [ ] 記録中のsummaryを正式議事録として承認・投稿できない。

## 権限と共有

- [ ] 開始者以外の一般ユーザーは議事録の閲覧・訂正・共有をできない。
- [ ] 元VCの閲覧権限を失った開始者も取得できない。
- [ ] 別サーバー・別会議のID・古い確認ボタンでは操作できない。
- [ ] 指定公開先に対する利用者の閲覧権限とBotの送信・添付・スレッド送信権限を検査する。利用者自身の投稿権限は必須ではない。
- [ ] 公開先・版の変更後に古い最終確認を使っても拒否され、最新の確認を要求される。
- [ ] 同じ版を連打しても一度だけ投稿し、メッセージIDを保存する。
- [ ] 訂正・再生成後の版は未承認に戻る。再公開する場合は新しい版を確認する。
- [ ] 開始者のDMが閉じていても `/minutes` で記録を取得できる。
- [ ] LANのブラウザからDiscord会議のIDを指定してもHTTP・WebSocket・ファイルを取得できない。

## 障害と測定

- [ ] STTを一人だけ失敗させる。欠損の可能性が残り、他の人の記録は続く。
- [ ] TTSだけ失敗させる。会議記録・議事録生成は続く。
- [ ] 議事録生成を失敗させる。原本は残り、再生成できる。
- [ ] 保存エラー・添付エラー・Discord送信の結果不明を区別する。保存できていない時に成功表示しない。
- [ ] 投稿成功後のDB保存失敗・タイムアウトを模擬し、statusが「送信結果要照合」となる。ボタン連打・再起動でも自動再送しない。
- [ ] 管理者の `/waigaya reconcile action:inspect` または `action:link url:<投稿URL>` でBot自身の会議・版を照合し、既存IDへ復旧する。
- [ ] 別Bot・別会議・別サーバーのURLでは紐付けない。Botの送信権限を失っていても、閲覧・履歴があれば既存投稿を照合できる。
- [ ] 未投稿が完全に照合でき、送信から10分以上経過した場合のみ `action:retry` の管理者確認で再試行可能にする。続けてminutesの最新確認から投稿する。
- [ ] 照合上限・履歴権限不足・取得障害では「未投稿」と断定しない。旧予約はURLと添付本文の検証を使い、無条件解除しない。
- [ ] 結果不明が残っている会議で保存先を変えて送信を逃れられない。公開済み投稿を削除してもSQLite原本・承認履歴は残る。
- [ ] 1時間以上の会議で原本の欠落・停止・文脈処理・費用を確認する。

測定記録には会議ID、モード、参加人数、時間、原発言件数、不要／有用な介入件数、重複・古い質問件数、誤った確定事項、議事録の修正数、API使用量を残す。人の声の開始からAI音声停止までの中央値・95パーセンタイルも測る。1時間会議の処理時間・DBとWAL容量・公開添付サイズも記録する。

同程度の会議を3モードで比べる。AIの発言数だけで良否を決めず、議論の役に立ち、邪魔しなかったかを参加者に確認する。
