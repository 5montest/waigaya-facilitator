# 固定Discord運用の手動受け入れ

2026年10月9日更新。**新版での実Discord通話・投稿は未実施。** 自動テストの成功で下記を完了扱いにしない。本番導入前のリリースゲートとして、管理者が結果・日時・対象コミット・権限を記入する。

## 導入前

- [ ] 旧Botとサーバーの正常停止、停止DBのバックアップ、検証用コピーからの復元、旧コード＋更新前DBでのロールバックを確認する。
- [ ] 実際のGuild ID、通常VC ID、GuildForum IDを確認する。別VC・別ギルド・未対応種別で開始しない。
- [ ] フォーラム閲覧ロールとBot権限を設定する。必須タグには未確認版に適用できるタグを用意する。
- [ ] 参加者へクラウドSTT・原音声非保存・原本保持・AI未確認議事録の自動公開を事前告知する。途中参加者・DM拒否者にも分かる導線を用意する。
- [ ] 新コマンドを再登録する。通常のstartにモード・保存先メニューがない。旧stopはAIだけ停止と説明される。
- [ ] サーバー→Botの順に起動する。起動・人の入室だけではVC参加・録音・公開しない。

## 開始一回→声の会話→無操作終了

- [ ] 2〜3人で固定VCへ入って引数なしstartを一回使う。開始前のVC通知、Bot入室、話者別STTを確認する。連打で二重会議・二重STTにならない。
- [ ] 「ワイガヤ、さっきの2案を整理して」「我ヶ谷、ここで懸念はある？」でコマンドなしの実音声回答を聞く。
- [ ] 「ワイガヤっていうBotを作っている」「前にワイガヤが言っていた件」で誤起動しない。呼称表記揺れや検出漏れを原文・依頼aliasで確認する。
- [ ] 名前だけへの短い聞き返しと連呼抑止、複数人連続質問の古い回答取消を確認する。
- [ ] Bot再生中「ちょっと待って」で停止し、残りを自動再開しない。人の声開始→停止の中央値・95パーセンタイルと測定方法を記録する。
- [ ] 一般質問と会議内の事実を区別する。声から公開・削除・権限変更を実行しない。AI回答が人の合意に混入しない。
- [ ] pauseで新規STT送信停止、resumeで新しい発言から再開。quiet／旧stopはAIだけ停止し、文字起こしを続ける。保守minutes設定ではTTSがゼロ。
- [ ] 人が残った無音では終了しない。全員退出から3分以内に戻れば同じID。pauseしてからの退出・復帰はpauseのまま。
- [ ] 全員退出後3分以上戻らず待つ。追加操作なしでドレイン・終了保存・Bot退出→正式生成→固定フォーラム一投稿になる。endとタイマーが競合しても一回。

## 投稿・訂正・プライバシー

- [ ] 親投稿に実会議日時・題名、AI生成・未確認、短い概要・決定候補・未決事項・アクション候補、版付きMarkdownがある。人の承認時刻を捏造しない。
- [ ] 原文全文・JSON・秘密値が自動公開されない。@everyone・ロールメンション・URLの埋め込みで予期せぬ通知が飛ばない。
- [ ] 閲覧ロールを変え、フォーラム親チャンネルの閲覧者だけが投稿を見る。原VC閲覧を失った人、第三者、他ギルドから非公開原本・autocompleteタイトルを取得できない。
- [ ] minutesで原発言訂正→要再確認→再生成、新版の同じ投稿への追記を確認する。旧版添付を残す。
- [ ] 任意の人の確認は別版・実確認者として追記し、元のAI未確認版を承認済みに書き換えない。
- [ ] タグなし・必須タグ・アーカイブ・ロック・投稿削除・添付容量上限で適切な動作と管理案内になる。無断で別親投稿を作らない。

## 障害・復旧・長時間

- [ ] STT、回答LLM、TTS、正式議事録LLM、Discord送信、DB保存の障害を分ける。回答失敗でも原本記録を続ける。管理通知に本文を載せず連投しない。
- [ ] 空会議は投稿省略、全STT欠損の疑いは異常と表示する。
- [ ] 送信成功後のDB保存失敗・送信タイムアウト・プロセス死亡をテスト環境で模擬し、結果不明で自動再送しない。reconcileで既存投稿へ紐付け、未送信確定時だけ再試行する。
- [ ] 無人猶予・終了途中・未公開・予約済みでBot／サーバーを再起動する。録音を自動再開せず、終了ジョブと公開履歴を復元し、重複投稿しない。
- [ ] 1時間相当の実会議について要約品質、修正箇所、呼称検出、古い返答、停止時間、使用量・推定費用、DB容量、生成・投稿時間を記録する。模擬負荷結果と区別する。

結果欄：対象コミット／日時／環境／参加人数／完了項目／未完理由／管理者名。会議本文やキーを公開チェック記録へ含めない。
