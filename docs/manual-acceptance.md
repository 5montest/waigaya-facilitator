# 実Discordの受け入れチェック

改善コードの自動テストとは別に、実際のBot・権限・マイクで実施する。未実施の項目を確認済みにしない。元音声を保存する設定は加えない。

## 更新前

- [ ] 稼働中の会議を参加者と確認して終了または一時停止する。
- [ ] Botと会議サーバーを停止し、`data/waigaya.sqlite` をバックアップする。
- [ ] 改善ブランチを導入し、認証ファイルと両方の環境設定を用意する。
- [ ] 旧会議を参照する必要があれば、実際のサーバー・VC・開始者IDで移行する。
- [ ] 会議サーバー→コマンド更新→Botの順に起動する。

## 議事録だけで完遂する

- [ ] 2〜3人で通常VCへ入る。Bot起動・入室だけでは記録されない。
- [ ] `/start` のモード選択を開く。未選択のままでは記録されない。
- [ ] 「議事録のみ」を選び、VCのチャットで送信・保存先とモードの通知を見る。
- [ ] 1〜2分話し、`/status` で記録中・AI音声OFFを確認する。
- [ ] `/ask voice:true` を使っても文字回答だけで、音声が出ない。
- [ ] `/pause` 後に話し、停止中の発言が文字起こしへ入っていない。
- [ ] `/resume` で同じIDを保ち、再開後の発言だけ記録される。
- [ ] `/finish` の確認をキャンセル・失効させる。記録は終了しない。
- [ ] 再度 `/finish` を確認し、原本を確定してBotが退出する。
- [ ] `/minutes` から議事録Markdown・構造化JSON・文字起こし原本を取得する。
- [ ] 下書きの根拠を原本で確認する。未確認の決定・担当・期限が確定されていない。
- [ ] 原発言を訂正すると旧議事録が要再確認になる。再生成で新しい版になる。
- [ ] 議事録項目を編集し、編集前の版と確認済み版が残る。
- [ ] 公開先を指定していない会議の全文がチャンネルへ投稿されない。

## 退出と再起動

- [ ] 人間が0人になり、Botだけ残る。新しい音声は記録せず猶予を表示する。
- [ ] 3分以内に戻る。同じ会議IDで続く。一時停止していた会議は停止のまま。
- [ ] 再び全員退出し、3分経過する。終了・議事録生成・退出が一度だけ起きる。
- [ ] 自動終了直前に手動終了しても生成が重ならない。
- [ ] 終了後にもう一度 `/start` すると新しいIDになる。
- [ ] 会議中にBotを停止・再起動する。勝手に記録せず、明示再開を要求する。
- [ ] 会議サーバーも再起動し、原本・版が残る。終了済み会議は終了状態のまま。
- [ ] 再起動後の一時停止会議を、録音再開せず `/finish` の確認で終了できる。
- [ ] `/summary` の生成中に `/finish` を使う。最後の発言を含む正式議事録が作られ、終了処理が止まらない。

## AIワイガヤと割り込み

- [ ] モードをAIワイガヤへ変更する。記録は同じIDで続く。
- [ ] 意味のある会話が増え、区切りで必要な時だけ発言する。holdも正常と扱う。
- [ ] 生成中に人が具体例を出す・問いを解消する。古い「具体的には？」が後から再生されない。
- [ ] AI発言中に「ちょっと待って」と話す。再生を停止し、残りを自動再開しない。
- [ ] 生成・待機中に議事録モードへ変更すると、TTSや後着音声が再生されない。
- [ ] quietではAIだけ停止し、記録は続く。pauseでは新しい音声送信も止まる。
- [ ] 相づち・環境音・エコーで過剰に停止しないか測る。実機で調整する。

## 権限と共有

- [ ] 開始者以外の一般ユーザーは議事録の閲覧・訂正・共有をできない。
- [ ] 元VCの閲覧権限を失った開始者も取得できない。
- [ ] 別サーバー・別会議のID・古い確認ボタンでは操作できない。
- [ ] 指定公開先に対する利用者の閲覧・投稿権限とBotの添付権限を検査する。
- [ ] 下書きを確認済みにし、公開先と版を確認して共有する。
- [ ] 同じ版を連打しても一度だけ投稿し、メッセージIDを保存する。
- [ ] 訂正・再生成後の版は未承認に戻る。再公開する場合は新しい版を確認する。
- [ ] 開始者のDMが閉じていても `/minutes` で記録を取得できる。
- [ ] LANのブラウザからDiscord会議のIDを指定してもHTTP・WebSocket・ファイルを取得できない。

## 障害と測定

- [ ] STTを一人だけ失敗させる。欠損の可能性が残り、他の人の記録は続く。
- [ ] TTSだけ失敗させる。会議記録・議事録生成は続く。
- [ ] 議事録生成を失敗させる。原本は残り、再生成できる。
- [ ] 保存エラー・添付エラー・Discord送信の結果不明を区別する。保存できていない時に成功表示しない。
- [ ] 公開予約の送信結果が不明なら、自動再送せず投稿先とSQLiteを照合する。
- [ ] 1時間以上の会議で原本の欠落・停止・文脈処理・費用を確認する。

測定記録には会議ID、モード、参加人数、時間、原発言件数、不要／有用な介入件数、重複・古い質問件数、誤った確定事項、議事録の修正数、API使用量を残す。人の声の開始からAI音声停止までの中央値・95パーセンタイルも測る。

同程度の会議を3モードで比べる。AIの発言数だけで良否を決めず、議論の役に立ち、邪魔しなかったかを参加者に確認する。
