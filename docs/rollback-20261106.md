## 4. 切り戻し手順（ロールバック）

```bash
cd /immich/media/agent-work/20261009-waigaya-fixed-ops
git rev-parse HEAD                    # 適用後HEADを記録
git switch -c rollback-20261106 BACKUP_HEAD   # または git reset --hard b5eaf47（承認時）
sudo systemctl restart waigaya.service
```

- **DBは戻さない**（新規保存された文字起こし・v2下書き・公開記録は監査記録として保持）。
  旧コードは`session_parts`/`events`の追加フィールドや未知状態を無視する設計（`normalizePublications`等）。
- **v2下書きの扱い**: 切り戻し後、v2の`minutesHistory`エントリは旧コードの`checkMinutes`を通らないため
  「再生成」してv1形式で作り直す。既に`approved`/`published`のv1版は不変で再公開不要。
- **通知スナップショット**: 旧コードは`publications[].mentions`を無視する。再送・二重通知の判断は
  旧コードの既存ルール（予約・照合）に戻る。適用期間中に通知済みの担当者へ再通知しないよう、
  切り戻し後は自動公開を一時停止し、`dry-run`で確認する。
- **チェックポイント**: v2のチェックポイントは旧コードのキーと一致しないため、再生成すると
  新しい旧形式チェックポイントが作られる。旧チェックポイントを削除しない。
- **別名辞書**: 旧コードは辞書ファイルを読まない。ファイルは残してよい（gitignore対象）。
- **DBの復元が必要な場合**は`backups/pre-20261106/live-validation.sqlite`から復元する。
  ただしその間の会議記録は失われるため、ユーザーの承認を得る。

## 5. 障害時の切り分け

| 症状 | 確認 | 対応 |
|---|---|---|
| 議事録生成が失敗 | `minutes_failed`イベント、`minutesStatus=failed`、lastError | 文字起こしは保持されている。`/waigaya finish`再試行、`settings`でモデル/接続を確認。v2スキーマ不適合なら`minutes-checkpoints`を消さずに再生成 |
| DeepSeek接続失敗 | ブリッジ`127.0.0.1:7684`の稼働、`ANTHROPIC_BASE_URL`/`WAIGAYA_MINUTES_BASE_URL`、キー有無 | `.env.local`の既存設定を確認。旧GLMへ戻す場合は`WAIGAYA_MINUTES_MODEL=glm-5.3-flash`（ブリッジがGLMも中継できる場合のみ） |
| メンション誤通知のおそれ | `publications[].mentions`、`describeMentionPlan`のdry-run | `notificationDefaults.enabled=false`に設定し再起動。誤った辞書エントリを無効化（`enabled:false`） |
| 二重通知 | 同一`actionIndex`+`ownerUserId`の通知記録 | 自動公開を停止。再送せず、投稿結果を`/reconcile`で照合 |
| 投稿失敗/結果不明 | 既存の`pending`/`needs_reconciliation` | 既存の`/reconcile`手順。**不明な送信を再送しない** |
