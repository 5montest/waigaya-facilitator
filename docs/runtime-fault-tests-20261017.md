# 実環境で起きる障害・処理の競合の追加検証

2026年10月17日。稼働コード `985ca8f` の適用後、追加の障害テストを依頼されたため実施した。編集・依存導入・テストには別のgit worktreeを使い、稼働中のBot、会議サーバー、原本DB、実Discord投稿には変更を加えていない。

## 方法と結果

新規22ケースを追加した。実ローカルHTTP／WebSocket／SQLite、実Opusのエンコード・デコード、模擬Discordイベントを組み合わせた。定期復旧ワーカーを止めないケース、通話接続が2.3秒遅れるケース、心拍停止からの検出、13秒のSTTドレイン待ちを含む。タイマーをすべて即時成功に置き換えてはいない。

STTの通信イベントは模擬WebSocket、LLM・TTS・Discord投稿は模擬API。通常の結合テストと同じく、実サービスの課金やサーバーへの投稿は発生しない。

各修正に先立ち、15ケースで旧挙動による失敗を再現した。関連テストの修正後確認は45件成功。その後、起動時の復旧・保存失敗・接続待ち中のエラー・13秒タイムアウトを加え、クリーンな `npm ci` 後の全体実行は196件成功、失敗0、skip 0、約68.1秒（Node 24.21.0 / ARM64）。その後の最終確認で強制退出と音声受信無効の2ケースを追加し、該当経路4件を単独で成功させた。最終全体実行は **198件成功、失敗0、skip 0、約64.0秒**。従来分が176件、追加分が22件。今回の両全体実行では既存の本筋テストのタイムアウトは起きなかったが、その再発がないことを保証する結果ではない。

| 想定した状況 | 確認結果・修正 |
|---|---|
| 通話接続が2秒以上遅れ、定期復旧が動く | 以前の誤停止修正が有効。文字起こし→音声回答→終了・一度だけ投稿まで確認 |

| 音声購読が同期例外を返す | 未捕捉例外になる経路を修正。該当話者の障害を記録し、次の発話で復旧可能 |
| Bot接続時にすでに人が話している | 発話開始イベントだけに頼らず、その時点で話している人を購読 |
| pause中から話し続けたままresume | 再開後の音声を購読。pause中の音声を遡って送らない |
| STTがエラーイベントなしで突然終了 | 正常終了との誤認を修正。該当ストリームを停止し、記録障害・欠損を残す |

| 心拍が途絶える | 実タイマーで検出。勝手に再接続・録音開始しない |
| 議事録生成が遅い | Botは先にVC退出。生成完了後の投稿は一度だけ |
| Discord送信結果が不明 | 定期走査でも再送・DM連投しない。原本と送信予約を保持 |

| 起動時の復旧一覧取得が遅れ、新規開始と重なる | このプロセスが開始・管理中の会議を誤停止しないよう修正 |
| SQLite保存が継続的に失敗 | 新規受信を停止。最後の保存済み原本を保持し、保存失敗を表示。ストレージ復旧後の処理も確認 |
| VC接続待ち中に非同期errorイベント | 未捕捉例外になる経路を修正。停止状態と接続障害を保存 |
| 最終STTが13秒で確定せず、切断イベントも重なる | 欠損を注記し、確定済み発言から終了・生成・投稿を一度だけ実行。後着の古い結果は不採用 |
| STT終了時の確定待ち中に切断 | 未確定結果を正常終了と誤表示する問題を修正 |
| STT終了待ち中にAPIエラー | エラーを無視する問題を修正。生のAPI応答は通知しない |
| 明示中断後に古いSTT結果が届く | 中断と障害を区別し、遅延結果を採用しないよう修正 |

| Discord側でBotの音声受信が無効になる | 開始時・会議中とも検出して停止。音声を受け取れないまま記録中と表示しない |

## 主な変更

- `src/discord/bot.js`：開始通知後の参加確認、既存発話の購読、受信例外と接続障害の処理、話者ごとのSTT健全性、起動時の復旧と開始処理の競合防止。
- `src/discord/transcription.js`：突然の終了を検出し、close・abortの完了通知を一度だけ行う。終了・中断後の遅延文字起こしを抑止。
- `src/openai-audio.js`：終了要求と明示中断を別に管理。確定待ち中のエラー・切断を記録欠損の可能性として通知し、失敗時の使用量を確定請求額と誤認しない。
- `test/helpers/fixed.js`：定期ワーカー、遅延した初期化、STTストリーム、議事録生成をテストから制御可能にした。従来のテストだけでなく、タイマーが動く条件を追加。
- `test/runtime-faults.test.js`：19件の結合・障害テスト。
- `test/openai-audio.test.js`：3件のSTTプロトコル回帰テスト。

SQLiteの破壊的変更、履歴削除、保存先・モードの変更はない。STT障害が残っている間も正常な話者の記録は続けるが、入力の健全性を確認できるまではAI音声回答を抑制する。接続切断時は安全に終了し、無断で録音を再開しない。
