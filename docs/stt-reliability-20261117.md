# 文字起こしの接続・確定待ちの修正（2026-11-17）

文字起こしの失敗を減らすため、接続の再利用、確定結果の待機、古い接続と新しい接続の分離を修正した。モデルは従来の `gpt-transcribe` を維持する。過去に失われた音声を復元する変更ではない。

## 短い沈黙で接続を作り直さない

従来はDiscord受信が500msの沈黙で区切られるたびにSTT接続も終了していた。今回から同じ話者の接続を再利用し、区切りごとに音声を確定要求する。

- 60秒間その話者の音声がなければ接続を閉じる。次の発言で新しく接続する。
- 接続開始から50分を超えたら、次の発言の開始前に接続を交代する。
- pause、全員退出、会議終了では接続を閉じる。pause中の新しい音声は送信しない。
- 送信音声から省いた無音時間を、文字起こしの時刻に戻す。結果の到着順が前後しても発言時刻を保持する。
- 100ms未満の音声区間は100msまで無音で補い、APIのcommit下限を満たす。原音声は保存しない。

## 結果が届いている途中の10秒切断を廃止

各commitを個別に管理し、30秒間進捗がなければ失敗とする。途中結果で待機期限を延ばすが、commitから最大120秒で打ち切る。別の発言が成功しても、応答がない発言の期限は延びない。

終了・pause時のドレイン上限は13秒から123秒へ変更した。通常は全結果の到着後すぐ終わる。systemdの停止猶予は150秒にし、アプリの確定待ちより先に強制終了されないようにする。ブラウザの確定待ちも同じ上限に合わせた。

完了イベントがcommitの確認より先に届く防御ケースも扱う。確定済みの発言を再び「未完了」として待たない。

## 古い接続の失敗は新しい受信を消さない

音声受信とSTT接続の所有関係を確認してから破棄する。交代前の接続が遅れて失敗しても、新しい受信、発話検知、再接続の待機時間を変更しない。障害があったことは欠損の可能性として記録する。

## 検証方法と限界

自動テストは模擬OpenAI応答、模擬Discord、実HTTP・WebSocket・SQLite・Opusを使う。短い発言の連続、逆順の確定、30秒無応答、120秒上限、一時停止・再開、接続交代、割り込み停止を確認する。実行結果はPRと反映記録に残す。

有料OpenAI APIへの追加呼び出し、実通話、Discordへのテスト投稿は行わない。実会議での認識率や失敗件数の改善幅は未確認。過去の `connect_failed` は接続先の詳細な応答を残していないため、原因をすべて特定したわけではない。

次の実会議では発言の欠落、終了までの待ち時間、`finalize_timeout` と接続失敗の件数を確認する。障害件数を、そのまま欠損した時間・発言数として扱わない。

## 反映と復旧

DBスキーマと既存記録は変更しない。会議・終了ジョブが動いていないことを確認し、SQLiteのバックアップを作成してからコードを更新・再起動する。固定チャンネル、認証キー、別名辞書は引き継ぐ。

問題があれば会議のない時間にサービスを停止し、変更前の `fcc21e0` に戻して起動する。DBの復元は通常不要。バックアップ時点以後の会議がある場合、古いDBを上書きするとその記録を失うため、コードの復旧とDBの復元は分けて判断する。停止猶予150秒は旧コードでも利用できる。

## 自動検証の実行結果

Node.js 24.21.0 / ARM64で `npm ci` を実行した後、次の全体テストを実行した。325件成功、失敗0、skip 0、約89.5秒。ブラウザは共有ホストのロックを取得して1インスタンスで実行した。

```bash

git diff --check

```

`git diff --check` は成功。差分の認証情報パターン検査は検出0件。`npm audit` は既存依存の `undici`（high）と `fast-uri`（moderate）の2件を検出した。今回、依存バージョンは変更していない。日本語文書のlintはSudachiPy未導入で実行できず、文面は目視で確認した。

最終確認では、終了済みのDiscord音声ストリームの遅延エラーが、再利用中のSTT接続を巻き込まないよう受信ストリーム自体も照合した。回帰ケースを1件追加し、関連48件が成功した（約38.4秒）。全体325件の実行後に行った追加検証である。
