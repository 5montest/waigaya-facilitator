# 我ヶ谷：Discord利用マニュアル

更新日：2026年10月15日

対象：PR #1の固定チャンネル版

**会議室Aで `/waigaya start` を1回実行します。あとは声で質問し、会議が終わったら全員退出してください。** Botが自動で終了し、議事録を指定フォーラムへ投稿します。

`start` だけならBotは自分から発言しません。呼びかけなければ議事録だけの運用になり、声で質問したときだけ音声で返答します。本筋を設定しても自動発言は始めません。まず短い手順を知りたい場合は [簡易説明書](quick-start.md) を読んでください。

このマニュアルは会議の参加者・開始担当者向けです。初めて使う場合は「会議を始める」から「議事録を読む」までを読んでください。訂正やトラブル対応は必要なときに参照します。管理者によるBotの起動・チャンネル設定が済んでいることを前提とします。

> 確認状況：合成音声による実AI処理、実VCへの音声送信、実フォーラムへの議事録・訂正版投稿は確認済みです。人のマイクによる会話・音声聴取・全員退出後の3分終了を通した実通話確認はまだです。以下は現在の実装に基づく操作案内です。

## 会議を始める：会議室Aでstartを1回

記録する場所と投稿先は固定されています。会議ごとに選び直す必要はありません。

| 用途 | チャンネル |
|---|---|
| 会話・記録 | [会議室A](https://discord.com/channels/1279446749970436236/1279446750498787390) |
| 議事録の自動投稿 | [議事録（テスト）](https://discord.com/channels/1279446749970436236/1557808517904338995) |

1. 会議室Aのボイス通話に参加します。
2. 参加者のうち1人が、Discordのチャット入力欄で `/waigaya start` を実行します。
3. 会議室Aのチャットに記録・AI送信・議事録自動公開の案内が出て、Botが通話に入ります。「会議を記録しています」の表示を確認してから話し始めてください。

モード選択、保存先指定、承認操作は不要です。会議名を付けたい場合だけ、startの `topic` に入力します。省略すると日時とVC名から自動で付けます。

会議の大筋が決まっている場合は、任意の `purpose` に目的・比較軸などを入力できます。入力しなくても開始でき、あとから声で指定できます。

Botがオンラインになっただけ、または人が会議室Aに入っただけでは記録は始まりません。ほかのVCからの開始はできません。開始案内を送れない場合も、記録を始めません。

開始には会議室Aへの参加・閲覧・接続権限と、投稿先フォーラムの閲覧権限が必要です。開始した人が、その会議の管理担当者になります。

## 声で質問する：最初に「ワイガヤ」と呼ぶ

通常は静かに記録します。質問したいときは、発言の最初に名前を呼んで、そのまま質問してください。`/ask` は不要です。

| 話しかけ方 | 期待する応答 |
|---|---|
| 「ワイガヤ、今の話をまとめて」 | 会議内容を短く整理 |
| 「ワイガヤ、A案とB案の違いを教えて」 | 会議で出た案の違いを説明 |
| 「ねえワイガヤ、まだ決まっていないことは？」 | 未決事項を説明 |
| 「ワイガヤ、ここで懸念はある？」 | 会議内容を踏まえて懸念を提示 |

開始した人以外も、会議室Aに参加中なら質問できます。名前だけ呼んだ場合は短く聞き返します。「ワイガヤっていうBotを作っている」「前にワイガヤが言っていた」のように、Botを話題にしただけでは原則応答しません。

回答は原則1〜2文です。音声認識と回答生成があるため、返答まで数秒以上かかる場合があります。人が話している間は再生開始を待ちます。Botが話している途中に人が話し始めると音声を止め、続きを勝手に再開しません。

会話の補足が入った場合は一度だけ最新の内容で回答を再検討します。質問が解決済みになった場合や、さらに会話が進んで回答が古くなった場合は、発言を見送ることがあります。複数の人が続けて呼びかけると、前の依頼より新しい依頼を優先します。

声で質問・要約を頼めるほか、次節の手順で会議の本筋を指定できます。「記録を削除して」「公開先を変えて」などの管理操作は、声だけでは実行しません。最新の外部情報を検索する機能もありません。

## 本筋を伝える：目的と比較軸を声で設定できる

会議を開始した人か管理担当者が、例えば次のように話してください。

> 「ワイガヤ、今日の目的は配線方式を決めること。コストと作業時間を比較したい」

目的と比較軸を指定した言葉のまま記録し、Botが短く読み返します。会議名は変えず、後の回答・比較・議事録で本筋を参照します。本筋の指定は、参加者全員の合意や決定の確定を意味しません。

| したいこと | 話しかけ方 |
|---|---|
| 本筋を確認する | 「ワイガヤ、今日の目的を教えて」 |
| 本筋を変更する | 「ワイガヤ、本筋をコストの比較に変更して」 |
| 扱わない話を伝える | 「ワイガヤ、今日の目的は配線方式の比較。旅行の話は扱わない」 |

本筋の確認はほかの参加者もできます。変更は開始した人か管理担当者が行います。`status` でも設定を確認できます。一時停止中・終了後の声の指示は受け付けません。指定した発言を訂正した場合は要再確認となり、会議中にもう一度本筋を指定するまで、古い設定は回答の判断軸や自動介入に使いません。

**本筋を設定しただけでは、Botは自動で発言しません。** 通常の議事録中心の運用では、引き続き呼びかけたときだけ返答します。

### 脱線したときの声かけは、必要な場合だけ有効にする

開始した人か管理担当者が「ワイガヤ、脱線したら声をかけて」と頼むと、本筋から外れた話が続く場合だけ、短く戻す提案を出します。先に本筋を設定してください。

本筋に関係する具体例や案の発散、一時的な雑談、話題がすでに戻った場合は発言を見送ります。判定にはAIを使うため、脱線を必ず検出できるわけではありません。人が話している間は再生せず、割り込みで止まった音声は再開しません。

止めたい場合は「ワイガヤ、脱線の声かけを止めて」。声かけの間隔は少なくとも45秒空け、新しい会話がなければ再検討しません。会議全体の自律進行を有効にする操作ではありません。

管理者が厳密な「議事録のみ」プリセットを選んでいる場合は、本筋の設定・確認をVCチャットへ文字で返し、音声は一切出しません。quiet中も音声は停止したままです。本筋と脱線通知の設定は会議ごとに保持し、新しい会議へは引き継ぎません。

## 会議を終える：全員が退出するだけ

会議が終わったら、人間の参加者が全員退出してください。手動の終了・承認・投稿操作は不要です。

```text
人間の参加者が0人になる
  → 3分の再参加猶予（新しい音声の送信は停止）
  → 残っている文字起こしの確定を待つ（最大13秒）
  → 記録終了・Bot退出
  → 議事録生成・フォーラム投稿
```

3分以内に人が戻れば、同じ会議を続けます。記録を一時停止していた場合は、戻っても停止のままです。終了した後にもう一度startを実行すると、新しい会議になります。

人が残っている間は、無音が続いても自動終了しません。Botが無人の会議室Aに残っていても、全員退出から3分以内なら通常の猶予動作です。議事録の生成・投稿はBot退出後も続くため、退出と同時に投稿が出るとは限りません。

発言がなかった会議は投稿を省略します。文字起こし障害で記録が欠けた疑いがある場合は、正常な議事録が完成したものとして扱いません。

## 議事録を読む：フォーラムの会議投稿を開く

終了後は「議事録（テスト）」フォーラムを開いてください。会議ごとに、日付・会議名付きの投稿を1つ作ります。

投稿には短い概要と版付きMarkdownファイルを載せます。詳細は添付の `minutes-v1.md` などをダウンロードして読めます。訂正版は同じ投稿の返信に追記し、過去の添付は残します。

日時は `2026/10/13 22:04〜22:07（日本時間）` のように表示します。概要・決定候補・未決事項は見出しと箇条書きで整理し、空の項目は省略します。長い内容は添付に載せます。長い会議IDや送信照合用IDは、投稿本文には表示しません。

自動投稿の表示は **「AI生成・未確認」** です。人が承認した議事録ではありません。決定候補と人が確認した決定を区別し、不明な担当者・期限を推測で埋めません。Bot自身の回答も、参加者の合意の証拠にはしません。

フォーラムのコメント欄で補足・確認の相談ができます。ただし、コメントを書いただけでは保存済みの議事録本文は更新されません。本文の訂正は次の手順を使います。

## 原文の確認・訂正は、開始した人か管理担当者が行う

フォーラムの投稿は閲覧権限がある人なら読めます。元の文字起こしや非公開の操作画面は、会議を開始した人、サーバー管理者、設定された管理ロールの人に限ります。元の会議室Aを閲覧・接続できる権限も必要です。

### 議事録・原文を非公開で取得する

`/waigaya minutes` を実行します。省略時は現在・直近の会議を対象とし、過去の会議は `meeting` の候補から選べます。

画面と添付は操作した本人だけに表示します。議事録Markdown、整理されたデータのJSON、文字起こし原文のMarkdownを取得できます。生成前やファイル出力障害時は、そろっていない場合があります。

### 誤りを訂正する

- 議事録の表現を直す：`minutes` →「項目を訂正」→ 対象項目を選んで修正。
- 聞き取りを直す：`minutes` →「原発言を訂正」→ 対象発言を修正。その後、`/waigaya minutes` の `action` で「再生成」を選びます。

訂正した議事録は新しい未確認版として扱います。終了後の正式議事録で、根拠などの検査を通れば同じフォーラム投稿へ自動追記します。原発言を直しただけでは、公開済みの添付は変わりません。再生成した新版と、フォーラムへの追記を確認してください。

内容を人が確認した記録も残したい場合は「人の確認を付けて追記」を押し、対象版と投稿先を確認して最終ボタンを押します。この操作は任意です。操作担当者の確認を記録するもので、参加者全員の合意を保証しません。

古い画面や確認ボタンが失効した場合は、`minutes` を開き直してください。訂正・確認画面には60秒の有効期限があります。

## 記録を止めたい・困ったときの操作

以下は普段の会議では不要です。会議の操作は開始した人か管理担当者が行い、記録の停止・再開・終了などは同じVCに参加して操作します。

| したいこと | 操作 | 結果 |
|---|---|---|
| 状態を知る | `/waigaya status` | 記録状態、回答待ち、議事録・投稿状態を本人だけに表示 |
| 記録を一時停止する | `/waigaya pause` | 新しい音声のAI送信・文字起こしを停止。停止前の確定処理は行う |
| 記録を再開する | `/waigaya resume` | 再開後の新しい発言から記録。停止中の会話は遡って記録しない |
| AI音声だけ止める | `/waigaya quiet` | 記録は継続。声で呼んでも返答しない |
| 今すぐ会議を終了する | `/waigaya end` | 確認ボタンなしで記録終了・Bot退出・議事録処理へ進む |
| 確認してから終了する | `/waigaya finish` | 確認ボタンを押して終了 |
| 操作の説明を見る | `/waigaya help` | 普段の使い方を表示 |

旧 `/waigaya stop` はquietと同じく、AI音声だけを止めます。会議の終了にはendを使ってください。quietの後にresumeを使っても、AI音声は再開しません。現在は固定版の通常メニューに音声再開の切替がないため、同じ会議で音声を戻したい場合は管理者へ相談してください。新しい会議は通常の呼びかけ応答で始まります。

| 困っていること | 確認・対応 |
|---|---|
| 呼びかけても返答がない | statusで記録中・AI音声停止・入力障害を確認。「ワイガヤ、今の話をまとめて」のように冒頭から呼びかけ直す |
| 回答の途中で止まった | 人の声による中断や入力障害の可能性。必要ならもう一度質問する |
| 議事録がまだ出ない | 3分猶予・文字起こし確定・議事録生成を待つ。開始担当者がstatusで進行状況を確認 |
| 「議事録生成失敗」と出た | minutesで取得できる原文を確認し、「再生成」を選ぶ |
| 「送信結果要照合」と出た | 管理者へ連絡。二重投稿を防ぐため自動再送を止めている。管理者が `/waigaya reconcile` で照合する |
| 「保存に失敗」と出た | 最新の発言が保存されたか確認できない状態。記録が残っていると決めつけず、管理者へ連絡する |
| Bot再起動後に記録が止まった | 自動で録音再開はしない。開始担当者がstatusを確認し、再開可能な会議ならresumeを実行 |

解決しない場合は、Botの管理者へ操作した時刻・コマンド・statusの障害表示を伝えてください。会議本文や非公開の添付を、閲覧制限のないチャンネルに貼り付けないでください。

## 記録・公開の範囲を確認して使う

記録中の音声はOpenAIへ送信します。元の音声ファイルは保存せず、文字起こし・議事録・訂正履歴はBotを動かす端末に保存します。

終了後の議事録は、固定フォーラムを閲覧できる全員に自動公開します。会議参加者だけの非公開投稿ではありません。文字起こし全文とJSONは自動公開しませんが、議事録にも会話の要点は載ります。公開したくない内容を話す前にpauseを使うか、記録対象ではない場所で話してください。

途中参加者には記録・公開について本人向けの案内を試みます。DMの受信設定などで届かない場合もあるため、開始担当者も口頭で知らせてください。

保存期限による自動削除・利用者向けの削除操作は未実装です。保存や削除の相談は管理者へ連絡してください。

用語：**VC** はDiscordのボイスチャンネル、**フォーラム** は会議ごとに投稿を並べる場所、**文字起こし** は発言を文字にした原文、**議事録** はその内容を整理した文書、**版** は訂正・再生成の履歴番号です。

管理者向けの詳細は [Discord設定手順](../discord-setup.md)、確認済み範囲は [実テスト記録](live-validation-20261013.md) を参照してください。
