## 保存・配信の負荷測定（今回再実行）

`npm run bench:storage` で旧全文保存方式と変更行保存方式を実際のSQLiteへ書き込み比較した。2026年10月9日、Node 24.21.0 / ARM64、同じホストの一時ファイル・WAL方式。架空1時間の600発言（各240文字）、再生進捗300回、合計903保存イベント、差分受信クライアント1つ、原発言訂正1件。API呼び出し・課金は0。ベンチマーク内では進捗の1秒制限を使わず、同数保存で比較した。

| 指標 | 旧全文方式 | 今回の変更行・差分方式 |
|---|---:|---:|
| 保存したJSON量 | 303,159,885 B | 1,763,177 B |
| 状態配信量 | 302,668,350 B | 648,625 B |
| SQLite WAL容量（checkpoint前） | 166,489,232 B | 24,415,152 B |
| 処理時間 | 59,384 ms | 47,643 ms |
| 復元した原発言 | 600件 | 600件 |

保存JSONは99.42%、配信量は99.79%、WAL容量は85.33%減少。復元した全状態・発言revision・訂正は等値検証した。処理時間は同期ディスク書き込みを含み、環境やキャッシュ、同じホストの検証負荷に左右される単回の比較。WAL容量は最終DB容量と同じではない。実1時間会議のAI品質・費用を測定した結果ではない。

機械可読な測定結果はローカルの `results/storage-benchmark.json` に保存する。原発言や承認済み本文を切り捨てず、モデル入力と保存・配信だけを効率化している。

- 修正後の自律発言を参加者が最後まで聞けること。
