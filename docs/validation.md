## 保存・配信の負荷測定

`npm run bench:storage` で旧全文保存方式と変更行保存方式を実際のSQLiteへ書き込み比較した。2026年10月9日、Node 24.21.0 / ARM64、同じホストの一時ファイル・WAL方式。架空1時間の600発言（各240文字）、再生進捗300回、合計903保存イベント、差分受信クライアント1つ、原発言訂正1件。API呼び出し・課金は0。ベンチマーク内では進捗の1秒制限を使わず、同数保存で比較した。

| 指標 | 旧全文方式 | 今回の変更行・差分方式 |
|---|---:|---:|
| 保存したJSON量 | 303,071,391 B | 1,691,840 B |
| 状態配信量 | 302,579,856 B | 648,527 B |
| SQLite WAL容量（checkpoint前） | 166,439,792 B | 24,415,152 B |
| 処理時間 | 63,934 ms | 58,299 ms |
| 復元した原発言 | 600件 | 600件 |

保存JSONは99.44%、配信量は99.79%、WAL容量は85.33%減少。復元した全状態・発言revision・訂正は等値検証した。処理時間は同期ディスク書き込みを含み、環境やキャッシュに左右される単回の比較。WAL容量は最終DB容量と同じではない。実1時間会議のAI品質・費用を測定した結果ではない。

機械可読な測定結果はローカルの `results/storage-benchmark.json` に保存する。原発言や承認済み本文を切り捨てず、モデル入力と保存・配信だけを効率化している。

## 確認が残る点

- 修正後の自律発言を参加者が最後まで聞けること。
- 長時間・多人数での発言頻度、品質、会議全体の費用。
- 相づち・雑音・エコーに対する割り込み停止の調整。
- スマホなど別端末での証明書設定と実マイク。
- 3モード、終了・議事録・訂正・確認後フォーラム投稿・版更新・照合復旧の実Discord動作。
- 分割要約と保存・配信は模擬大量発言で確認済み。1時間以上の実会議の品質・費用は未確認。最終入力上限120,000文字は残し、統合失敗時も原本を保持する。
